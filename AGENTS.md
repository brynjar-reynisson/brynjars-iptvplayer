# AGENTS.md

Rust Windows desktop IPTV player (browse + play in one window, with persistent stream retry). Design: `docs/superpowers/specs/2026-10-17-iptv-player-design.md`.

## Rules
- Playlist URL/credentials live only in gitignored `config.toml`. Never commit it, the sample playlists, or the cache; never print credentialed URLs in logs/errors.
- Branches: `feature/...`, `bugfix/...`. Use `git -C <path>`. Update this file and docs when committing a feature branch.
- Add new source files to git.
- Build + deploy the release folder (`dist\iptv-player`, the pinned taskbar shortcut's target): use the project skill `.claude/skills/build-and-deploy/SKILL.md` (checks the app is not running, runs tests, `scripts/package-release.ps1`; keeps `config.toml`, cache and favorites).
- Known gaps, manual checks still to do and ideas are tracked in `docs/follow-ups.md`; update it when you fix or find one.
- Sample playlist: `<samples dir>\<playlist>.m3u`, in a samples folder outside the repo (contains credentials). Its file name contains a credential segment: never write the path or file name into tracked files or commit messages (read it at run time, e.g. via a glob or `IPTV_SAMPLE`).

## Build / run
- Toolchain: Rust stable, MSVC (`rustup default stable-x86_64-pc-windows-msvc`; needs VS Build Tools with the C++ workload). Run cargo from a normal shell with `%USERPROFILE%\.cargo\bin` on PATH.
- User docs: `README.md` (setup, keys, flags, known limitations). Release folder: `scripts/package-release.ps1 [-Out <dir>]` builds release and copies `iptv-player.exe` + `libmpv-2.dll` + `config.example.toml` to `dist/iptv-player/` (gitignored). Verified: that folder runs standalone (exe + DLL + `config.toml`, PATH reduced to System32; data dir = exe folder).
- Line endings: `.gitattributes` has `* text=auto eol=lf`. Some files are committed with CRLF (e.g. `mpv_backend.rs`, `cache.rs`, `redact.rs`, `series.rs`, the spec); git leaves CRLF blobs alone under `text=auto`, so keep each file's existing endings when editing (Git Bash `sed -i` strips CR: avoid it on CRLF files) and do not mass-renormalise.
- Workspace: `crates/iptv` (library: parsing, config, redaction, ...) and `crates/iptv-player` (egui binary).
- Series: `iptv::series` groups Kind::Series entries into shows/seasons (strips 2-letter language prefixes like `NC - `/`SE:`/`Vod:`, keeps year in show name, unparsed go to `(Unsorted)`); exposed via `Library::shows()`.
- Playback retry: `iptv::supervisor::Supervisor<B: Backend>` is a pure state machine (time passed in as `Instant`). Every `Backend::load` (play or retry) gets a new generation; the backend must tag events with it, stale ones are ignored. Backoff 0.5/1/2/3 s (auth 3/6/12/15 s, unavailable 3/6/10 s; all forever), reset after 10 s stable playing; pre-Started timeout 30 s VOD / 15 s live, +15 s per failed attempt (cap 120 s, extended by progress events, absolute cap 180 s after load); post-Started Buffering(true) stall watchdog 15 s (never report user pause/seek as Buffering); VOD `Ended` within 5 s of duration = `Finished`, else resume at last position. Never put the URL in its Debug/logs.
- `cargo test -p iptv` runs unit tests. `cargo run -p iptv-player` runs the app (`--release` for real use: debug builds are much slower with the full playlist).
- `cargo test --workspace` also runs the `iptv-player` unit tests (pure mpv mapping/scrubbing, and the GUI-free app state in `src/state/`). `cargo run -p iptv-player --example retry_demo` is the headless end-to-end retry check with real libmpv (needs `ffmpeg` on PATH; uses ports 8097-8099 on 127.0.0.1; prints a status timeline and `RESULT: ALL CHECKS OK`).
- Console: release builds use `windows_subsystem = "windows"` (no console window from Explorer; verified: no conhost child, debug build has one), and `main` calls `AttachConsole(ATTACH_PARENT_PROCESS)` only with `--console` (otherwise the stderr text lands after the shell's prompt and looks like a hung prompt) (`extern "system"` declaration, no extra crate) so stderr still reaches the terminal it was started from (verified in a real console) and redirected handles keep working. The terminal prompt returns at once; output appears after it. Debug builds and `retry_demo` stay console programs.
- App CLI: `iptv-player [--data-dir <path>] [--playlist-file <path.m3u>] [--console]`. `--data-dir` overrides where `config.toml`, `cache/`, `favorites.json` and `settings.json` live. Dev flag `--playlist-file` parses a LOCAL `.m3u` instead of downloading `playlist_url` (no `config.toml` needed); the result is still cached under the data dir, and Refresh (F5) re-reads the file. Startup timings go to stderr (`startup: first frame after N ms`, `startup: library ready after N ms`), plus `slow frame: N ms` whenever building the UI takes > 25 ms.
- Manual GUI test with local streams: a fake data dir plus an `.m3u` whose live entries point at ffmpeg servers, e.g. `#EXTINF:-1 tvg-id="a" group-title="Testland - Main",Test One` / `http://127.0.0.1:8191/fakeuser/fakepass/101`, served by `ffmpeg -re -f lavfi -i testsrc=size=640x360:rate=25 -f mpegts -listen 1 http://127.0.0.1:8191/fakeuser/fakepass/101`. ffmpeg's listener checks the request path (wrong path = HTTP 404) and serves one client then exits, so restart it in a loop for channel switching. Port 8091 is taken by another service on the dev machine; use 8191+.
- App structure (Task 11): `src/state/` is GUI-free and unit-tested (`data` = startup/refresh state machine: Loading / Ready / NoConfig / RefreshFailed + refresh Running/Failed{can_force}; `live` = country + filter + channel list; `favs` = favorites rows, toggle+save (reverted on save error), unavailable = not playable; `nav::ChannelList` = cursor with wrap; `playback` = what plays (name/key/url kept; entry index is `Option`) plus the Up/Down list snapshot; on a library swap `Playback::rebase` re-points it by favorite key and drops the old `Arc<Library>` (~250 MB), and a channel that vanished keeps playing marked "not in playlist"; `zap::Debounce` = Up/Down channel-switch debounce; `data` starts at most one refresh per session automatically: a refresh the user already requested (running, done or failed) suppresses the stale-cache one). `src/ui/` is the thin egui layer (`mod.rs` App, keys, panels, status line; `live.rs` virtualised lists via `ScrollArea::show_rows` with fixed 22 pt rows; `player.rs` supervisor + renderer + overlay). Cache load + `Library::build` run on a background thread (`fetch::load_cached`); refresh via `Refresher`. Movies/Series (Task 12): `state::vod` = `SearchList` (query + results with a generation: only the answer to the latest request is adopted, selection kept by favorite key / show name, results cleared at once on a library swap and re-searched), `SeriesBrowser`/`OpenShow` (show -> season headers -> episodes; cursor skips headers; `(Unsorted)` episodes and unparsed names show the full entry name, others `S01E02 - title` via `iptv::series::episode_label`), hidden-group filtering (`search_movies`/`search_shows`/`episode_rows`, limit 500 applied after filtering; `search_shows` also returns `(Unsorted)` when one of its episodes matches by its own name, never cut by the limit, and opening it then starts on that episode) and `SearchWorker` (one background thread, coalesces queued requests per scope; searches never run on the UI thread: real sample max ~22 ms; if the thread dies, `poll`/`submit` report it, the lists `abort()` their "Searching…" and the App respawns the worker). `vod_groups` (~30 ms, per-group movie/episode counts) is computed on a thread per library; `group_choices` adds hidden groups that left the playlist ("not in playlist") so they can be unhidden; the Groups menu has a filter box and "Show all"; the empty-query hint counts only visible entries and "All groups hidden" replaces it when nothing is visible. Only the visible list is scrolled when a search answer arrives; a VOD finish never switches the visible tab. `ui/vod.rs` draws the search row (right-to-left: Groups menu, then the box filling the rest, or the resizable panel grows every frame), result lists and episodes. `playback::queue_zap` drops a pending zap that returns to the loaded key or targets VOD; `rebase_pending` drops a pending zap whose channel left the playlist; `enter_action` opens the player (cancelling a pending zap) when Enter hits the loaded entry. A live `Playback`'s Up/Down list keeps only live entries. VOD `Status::Finished` stops and returns to the list it came from (entry selected), no autoplay.
- Settings: `iptv::settings::Settings` = `settings.json` beside `favorites.json`: `{"version":1,"hidden_groups":[...]}` (group titles hidden from Movies/Series results, edited in the Groups menu). Atomic writes; an unreadable/unknown-version file is moved aside to `settings.json.bad[.N]` (`fsutil::backup_path`), never deleted; if that move fails, `save` refuses.
- Keys: click/Enter = play selected (Enter or double-click on the playing row = full player view; double-click the video toggles it), Up/Down = move selection and, while playing, switch channel (wraps; in the full view walks the list playback started from). The switch is debounced: the selection moves on every key, but the stream is only loaded after `ZAP_DELAY` (300 ms) without further navigation, so holding Down opens one connection (the final target), not one per key repeat, which could trip the provider's connection limit. Click/Enter play immediately and cancel a pending switch; Esc cancels it too. F = toggle favorite (Favorites tab: the row under the cursor, so an unavailable favorite can be removed while something plays; other tabs: playing channel, else selected row), Space = pause (mpv `pause` only: never Buffering, so it never trips the stall watchdog), Esc = leave filter box / stop playback and leave the player view / clear filter, F5 = refresh, Ctrl+F or `/` = channel filter (Movies/Series: their search box). Navigating back to the loaded channel within the debounce window drops the pending switch (no reload). Movies/Series: the search box is focused when the tab opens and results update as you type (empty query = hint, not the whole list); Up/Down only move the cursor (never auto-play, no zap; also no zap while VOD plays), click/Enter play at once as VOD (Enter with nothing selected selects the first result), Series: Enter/click opens a show, Backspace/Left (outside the search box) or Esc go back to the shows, `< Shows` button too. Favorites of movies/episodes play as VOD (`is_live` from `Entry.kind`). Egui's default fonts lack symbols like arrows, stars and play triangles: draw markers as shapes or use plain text.
- Refresh safety net: `fetch` refuses to replace the cache when the new playlist has < 50% of the cached entries (`fetch::is_shrink_refusal(msg)`); the UI then shows the reason, a hint and a "Force refresh" button, which uses `Refresher::spawn_forced` / `RefreshOptions { force: true }` (skips only that check). `fetch::Source::{Url, File}` + `Refresher::spawn_source` cover `--playlist-file`.
- User-Agent: `config.toml` key `user_agent` (optional, trimmed; blank/missing = `iptv::config::DEFAULT_USER_AGENT` = `VLC/3.0.20 LibVLC/3.0.20`; control characters/line breaks are rejected with an error naming the file and key, never the URL).
  - The real provider answers HTTP 454 to requests without a User-Agent (reqwest sends none by default) and 200 to common player UAs.
  - The value is sent in two places:
    - Playlist downloads: `reqwest::blocking::Client::builder().user_agent(..)`, so redirects carry it too. Set via `RefreshOptions { force, user_agent }` or `Refresher::spawn/spawn_forced/try_spawn(url, dir, ua)`; `fetch::download` uses the default.
    - Stream requests: mpv option `user-agent` (`MpvOptions::user_agent` -> `mpv_backend::init_options`). Verified in `retry_demo` step 5a: mpv's libcurl requests carry it.
  - The UI reads it at startup (player) and again on every refresh request (downloads).
  - A playlist status without a standard reason (e.g. 454) fails as `server returned HTTP 454 (blocked? check user_agent in config.toml)`; known statuses read `server returned HTTP 404 Not Found`.
- Countries: `Library::build_with_top(entries, top)` sorts live countries alphabetically (normalised: case/diacritics), "Other" last, `top_country` (config.toml, optional, trimmed) first. `fetch::load_cached(dir, top)` and `RefreshOptions.top_country` carry it; the UI reads it at startup and on each refresh request.
- Fullscreen: the square button at the video's bottom right, F11 or Alt+Enter call `App::set_fullscreen`: OS fullscreen + `View::Player` (no selector); `fs_return_view` remembers the view to restore. While fullscreen, Esc only leaves it.
- Icon: `crates/iptv-player/assets/icon.ico` is embedded as the exe icon (`icon.rc` + `embed-resource` in build.rs, needs the Windows SDK `rc.exe`); `assets/icon_64.rgba` is the window icon (`ViewportBuilder::with_icon`).
- Exit: a 5 s watchdog thread starts on close request; `App::on_exit` stops playback, then calls `process::exit(0)` (plus a 3 s watchdog thread) because the process was seen lingering after the window closed.
- Config: copy `config.example.toml` to `config.toml` (gitignored) beside the exe (or in `--data-dir` / `IPTV_DATA_DIR`) and set `playlist_url`. Lookup order: CLI, env, exe directory. Always print URLs via `iptv::redact::redact_url` (fails closed: userinfo, every path segment between the credential start (after a `movie`/`series`/`live` segment, else the first segment of a 3+ segment path) and the final id, non-allowlisted query values, bare query tokens and fragments become `***`; text without `://` is left unchanged). `Config`, `Entry`, `Library`, `CacheData` and `DataState` have manual `Debug` impls that never print URLs, logos or messages (`Entry` shows kind/id/name/group); keep it that way for any new type that holds them. Favorite keys: `{kind}:{id}` only for an all-digit stream id (`playlist::stream_id`), else `{kind}:name:{normalized name}|{group}`, so third-party `.../master.m3u8` channels get distinct keys; duplicate name+group pairs share a key (first wins in `find_by_key`). Live countries come from the group prefix before " - "; groups without a prefix, with an empty prefix or with the prefix "Other" all go to one "Other" country, always listed last.
- Dependencies are added per task. `iptv-player` has `eframe` 0.37 (glow only, no wgpu) and `libmpv2-sys` 4.0.1; it is a lib (`iptv_player`, shared with examples) plus the `iptv-player` binary.

## libmpv
- `*.dll` and `/libmpv/` are gitignored. Get the x86_64 dev package from https://github.com/shinchiro/mpv-winbuild-cmake/releases (`mpv-dev-x86_64-<date>-git-<hash>.7z`, e.g. `gh release download <tag> -R shinchiro/mpv-winbuild-cmake -p 'mpv-dev-x86_64-2*'`) and extract with 7-Zip. Verified with `mpv v0.41.0-1200-gdde067107` (client API 2.x).
- Put `libmpv-2.dll` and `mpv.lib` in `./libmpv/`. `crates/iptv-player/build.rs` adds `<repo>/libmpv` to the link search path (relative to `CARGO_MANIFEST_DIR`, no env vars needed) and hard-links/copies `libmpv-2.dll` into `target/<profile>/`, `deps/` and `examples/` so the exe, test and example binaries start. If the folder is missing the build script only warns and linking fails with "cannot open input file 'mpv.lib'". For a release folder, copy the DLL beside `iptv-player.exe`.
- `mpv.lib` (MSVC import library) is generated from the DLL, since the package only ships a MinGW `libmpv.dll.a`: list exports with `dumpbin /exports libmpv-2.dll`, write `mpv.def` (`LIBRARY libmpv-2.dll` + `EXPORTS` + the `mpv_*` names), then `lib /def:mpv.def /out:libmpv\mpv.lib /machine:x64` from a VS developer prompt. Verified working (Task 10) with `libmpv2-sys` 4.0.1, which emits `rustc-link-lib=mpv`; its pregenerated bindings compile on Windows (their layout asserts pass).
- Decision: `iptv-player` uses `libmpv2-sys` + a hand-written safe wrapper (`src/mpv_backend.rs`), not the high-level `libmpv2` 6.0 crate: its events drop `playlist_entry_id` (needed to tag events with the right generation) and the end-file error code, and its `RenderContext<'a>` borrows the `Mpv`, which does not fit a long-lived backend whose renderer is shared with a `Send + Sync` egui paint callback.
- Rendering: OpenGL render API (`vo=libmpv`) inside an `egui_glow::CallbackFn` (eframe `glow` renderer; GL functions from `CreationContext::get_proc_address`). mpv renders into an offscreen FBO the size of the callback rect, which is then blitted into the rect (mpv sets its viewport to the whole target, so rendering straight into the window framebuffer would cover the whole window). Free the render context in `App::on_exit` (GL context current) via `MpvRenderer::destroy`. The `wid` child-window fallback was not needed.
- Events: `loadfile <url> replace -1 [start=<secs>]` via `mpv_command_ret` returns the `playlist_entry_id`, which maps to the supervisor generation (needs mpv >= 0.38, checked at startup). Attribution is the pure, unit-tested `mpv_backend::EventMapper` (decoded `RawEvent`s + time in, `(generation, PlayerEvent)` out). START_FILE/END_FILE carry the id; property changes and log lines are attributed to the entry between them. `Started` = first PLAYBACK_RESTART; `Buffering` = `paused-for-cache && !pause && !seeking` (cache/seek flags reset at START_FILE); end-file eof -> `Ended`, error -> one `Error(class)`, stop (user stop or replacement) -> nothing.
- mpv delivers log/property events only when its regular queue is empty, so they can arrive late: an error/eof end waits `END_GRACE` (250 ms) for its log lines; stream log lines within `ATTRIBUTION_WINDOW` (500 ms, shorter than the minimum retry gap) after the previous entry ended are dropped instead of being given to the new entry; the EOF->Auth upgrade only uses lines logged after the entry's PLAYBACK_RESTART; before PLAYBACK_RESTART, `time-pos` is only passed on if >= the entry's `start=` (never for live) and `duration` is held until restart, so the old file's values cannot overwrite the resume point.
- Error classification: only stream/network log prefixes are scraped (`ffmpeg`, `ffmpeg/demuxer`, `stream*`, `lavf`, `curl`, `demux*`, `http`, `tcp`, `tls`, `network`; not `cplayer`, `file`, decoders, outputs), and URLs (`<url>`) and decimal numbers (`<num>`) are neutralised before `ErrorClass::from_message`, so a channel id like `/401.ts` or a timestamp `458.200` never reads as an auth status. Classes: `Auth` = whole-token 401/403/458/459 or connection-limit/account wording ("max connections", "too many connections", "simultaneous", "connection limit", "unauthorized", "forbidden"); `Unavailable` = 404/407/410, "not found" (not host lookups) and lavf's generic "4XX Client Error, but not one of 40{0,1,3,4}"; `Network` = refused/timeouts/DNS/TLS/5xx; else `Other`. The supervisor turns them into `Status::Reconnecting { attempt, kind: RetryKind::{Network, Auth, Unavailable} }` (Other -> Network); overlay texts in `state::status_text` ("Reconnecting…", "Account rejected or too many connections — retrying", "Channel unavailable (off-air?) — retrying"). An EOF whose post-restart log lines classify as Auth/Unavailable is reported as that error.
- Off-air event channels (seen on the real provider): the server answers HTTP 407 (text/html) instantly. mpv's libcurl backend logs `[curl] error: HTTP error 407` (verified against a local 407 server in `retry_demo` step 5c and one real off-air channel) -> `Unavailable`, retried 3/6/10 s forever so the channel starts when it goes live. `retry_demo --url-from-playlist <file.m3u> <group-title> <index> <secs>` plays one real entry headlessly and prints only masked text (no URL, host or account segments); use one connection at a time.
- Call `MpvRenderer::destroy(gl)` in `App::on_exit` (after `Supervisor::stop`; `ui::player::Player::shutdown` does both); dropping the renderer without it logs a warning and leaks the FBO. Hand-tested in Task 11 at 125 % DPI: resize during playback, video rect right of the browse panels (non-origin) and full-window, no egui corruption after video. `paint_callback` disables `SCISSOR_TEST` while mpv renders into its FBO (egui leaves it on with the clip rect in window coordinates, which would clip a non-origin render), resets unpack pixel-store state / `PIXEL_UNPACK_BUFFER` / active texture, and scissors the blit to the clip rect.
- This mpv build opens http(s) through its own libcurl backend (log prefix `curl`, e.g. `[curl] HTTP error 401`, `[curl] Could not connect to server`), so the `stream-lavf-o` reconnect options only apply when lavf's http is used; the supervisor does the real retrying. `ytdl=no` is required (the built-in ytdl hook otherwise spawns youtube-dl for every http URL).
- Credentials: `terminal=no`, `msg-level=all=warn`, only warn+ log messages are requested, no mpv log file, and every message goes through `mpv_backend::scrub` (redacts loaded URLs, their paths and anything shaped `scheme://...`) before it is stored or printed.
